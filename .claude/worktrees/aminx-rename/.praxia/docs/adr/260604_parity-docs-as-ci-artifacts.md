## Decision

Parity validation documentation is generated automatically by CI parity jobs and deployed as build artifacts. Manual maintenance of parity docs in the repository is discontinued.

## Rationale

Hand-maintained parity documentation has consistently diverged from actual parity test results. The single source of truth for parity validation is the CI job output — specifically, the JSON reports and summary tables generated at test time.

Key observations:
- Manual docs (`docs/parity/`) require synchronization with test code whenever tests change
- That synchronization is manual, error-prone, and frequently omitted
- CI job output is authoritative and always in sync with what tests actually run
- Storing both versions creates maintenance burden and risk of conflicting information

Automating document generation eliminates the synchronization problem entirely.

## Consequences

### What Changes
1. CI parity jobs (`.github/workflows/parity-*.yml`) write detailed reports to build artifacts
2. Manual parity docs in `docs/parity/` are archived (see decision history)
3. Release notes and user-facing docs reference CI artifact reports instead of manual docs
4. The parity test matrix is the single source of truth

### What Stays the Same
- Test code and test logic remain in the repo (parity tests in `src/tests/parity/`)
- CI job frequency and coverage unchanged
- Parity thresholds and tolerance settings remain configurable

### Maintenance Burden
- Reduced: no manual syncing of docs with code
- Shifted: docs generation happens in CI, not in prose writing
- Benefit: drift detection automatic (artifact mismatch raises alarm)

## Alternatives Considered

1. **Manual syncing discipline** — Explicitly staff a person to sync docs with tests after each change. Rejected: human error rate too high, no enforcement mechanism.

2. **Dual system with automated checks** — Keep manual docs but add CI validation that they match current tests. Rejected: Still requires maintenance; adds CI complexity.

3. **CI artifact link in README** — Docs link to latest build artifacts; no local docs. Partial solution accepted; see Consequences.

## Implementation Notes

- Archive `docs/parity/*.md` into `.praxia/docs/archive/`
- Update `docs/README.md` to direct readers to CI artifacts
- Ensure CI artifacts are retained for ≥30 days (check GitHub Actions retention policy)
- Add link in release checklist to latest parity report
