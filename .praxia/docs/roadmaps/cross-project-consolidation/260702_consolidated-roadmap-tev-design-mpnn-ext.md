# Brainstorm: Consolidated roadmap: tev_design + mpnn_ext, folding in mistypotts and aminx per their actual roles

## Problem Frame
Fixed constraints (cannot change): (a) aminx must remain a pure infra/substrate project — it does not own research epics, per already-decided policy; (b) the W1a.1 null result stands as-is — we are not re-litigating the science, only deciding what roadmap step follows it; (c) tev_design's necklace campaign has a real, already-documented dependency on wave-coloring validation — that dependency direction is fixed, not up for debate; (d) mistypotts's completed science (KaiB/1WCL, Gate 15 PottsMPNN-adapter) stays wherever mistypotts lands — we are not proposing to redo or move that work, only its administrative/roadmap home; (e) the aminx.tiling/xtrax migration (#1541) is a known, unscheduled dependency — we're not solving it here, just deciding how to sequence around it.\n\nNegotiable: mistypotts's administrative home (mpnn_ext vs tev_design charter); the specific enforcement mechanism for the aminx boundary; whether tooling debt becomes its own epic or stays distributed; the exact next action for WAVE (halt-and-pivot vs proceed-with-caveat); how granular the retirement list is; whether the 5 existing aminx wave-color commits get reverted/moved or just re-attributed in place.

- [user] AMINX/MPNN_EXT BOUNDARY ENFORCEMENT: (a) Hard mechanical gate — mpnn_ext epics touching aminx internals must land via PR against aminx from a mpnn_ext-owned branch/fork, submodule-pointer-bump only, no direct research commits in aminx history going forward. (c) Full move — physically move the wave-color decode-path code out of aminx into mpnn_ext as a dependency that patches aminx via monkey-patch/plugin interface, so aminx literally cannot contain this class of code.
- [user] RETROACTIVE COMMIT HANDLING (5 existing wave-color commits in aminx): (a) Leave in place, add a decision doc in aminx re-attributing provenance to mpnn_ext epic #2871, cross-link from mpnn_ext's own docs. (b) Cherry-pick/move the commits into mpnn_ext as a vendored patch, revert from aminx, re-apply via the new PR channel. (c) Leave in place permanently as an accepted exception, documented as "epic 0 grandfather," with boundary enforcement starting only from the next epic forward.
- [user] WAVE EPIC NEXT STEP: (a) Halt W1a.2/W1a.3 immediately, pivot spend entirely to the Jacobian-sensitivity probe as a new sub-epic (W1a.1b) testing the general decode-order-sensitivity question via a different construction. (b) Run Jacobian probe and W1a.2 variance battery in parallel since they test different things and W1a.2 doesn't strictly depend on the coloring premise. (c) Halt the whole WAVE epic pending a scoping re-review, given the null plus the necklace-campaign blocking dependency — don't presume the Jacobian probe is the right next test without re-scoping first.
