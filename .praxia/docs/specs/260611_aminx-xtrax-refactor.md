# Brainstorm: Architecture, sequencing, testing, and packaging strategy for refactoring aminx to leverage the xtrax library — moving domain-agnostic primitives (tiling, high-performance output sinks, inference-plan/runner control flow) into xtrax, rebuilding aminx training on xtrax training primitives, while keeping protein-specific code in aminx and not regressing inference-path performance.

## Problem Frame
FIXED constraints (cannot change):
- Inference-path performance must not regress (io_callback drain, memory-estimation planner, ArrayRecord/HDF5 read, JIT recompile on static bundle fields are the hotspots).
- xtrax tiling is genuinely THINNER than aminx (lacks Scan.init/CarrySpec/CarryShape/rich DedupSpec) — aminx cannot delete its tiling copies until xtrax reaches parity; this is a hard ordering dependency.
- Protein-specific code (5 bundles: atom_37/residue_index/tie_group_map, domain losses/metrics/diffusion/dataloading) STAYS in aminx.
- Must bump aminx to Python 3.13 to depend on xtrax (xtrax requires >=3.13).
- The 12 move-candidate modules are DAG-clean (protein refs are TYPE_CHECKING-only) — this is verified ground truth.
- ADR 260605 boundary discipline must be preserved: the ruff TID251 ban currently catches aminx.* paths but NOT xtrax.*, so moving code silently bypasses the boundary lint — an equivalent boundary guard MUST be added.
- Two repos exist (aminx, xtrax); xtrax v0.2.0 is published to PyPI; xtrax must be developable in lockstep (editable path ../xtrax).

NEGOTIABLE:
- Sequencing/order of the move (upgrade-xtrax-first vs thin-adapter-where-ahead vs vertical-slice vs big-bang vs generic-skeleton).
- Packaging mechanism (editable-path pin vs uv-workspace vs optional-extra).
- make_axis_dispatch unification approach (rename-aminx vs factory-over-executor vs adopt-eager).
- StageBundle reconciliation (loosen xtrax validator vs wrap aminx StageSet).
- Checkpoint migration approach (metrics→extras mapping; whether to ship migration tooling for old Composite ckpts).
- Perf-regression guard mechanism (pytest-benchmark gate vs bathos-sidecar cluster bench on the inference path).
- Testing strategy (shared conftest vs aminx-owns-parity; whether parity is cluster-gated).

## Idea Pool
- [ai] Upgrade-xtrax-first: Bring xtrax tiling+training to full aminx parity as cross-repo work (add Scan.init/CarrySpec/CarryShape/rich DedupSpec, reconcile make_axis_dispatch semantics, loosen StageBundle), publish/pin xtrax, then aminx depends and deletes its local copies in one downstream pass. Eliminates the thinness blocker before any aminx deletion.
- [ai] Thin-adapter / depend-where-ahead: Adopt xtrax ONLY where it is already at-or-ahead of aminx today (ResumableState, optim, checkpoint, sparse, safe_map/safe_scan). Defer the entire tiling move until xtrax independently catches up. Maximizes early adoption with zero cross-repo blocking work; tiling stays in aminx indefinitely until justified.
- [ai] Vertical-slice incremental: Move one cohesive slice end-to-end at a time (training → tiling → inference runner/host sinks), with a parity gate between slices that must pass before the next slice starts. Each slice is independently shippable and revertible; the inference-runner slice lands last so perf risk is isolated.
- [ai] Big-bang coordinated cross-repo flip: Upgrade xtrax + move all 12 modules + flip all imports + add boundary lint in one synchronized atomic change across both repos. Single review, single CI gate, no intermediate hybrid states; highest blast radius but no lingering dual-ownership.
- [ai] Generic-skeleton + protein-subclass: Extract generic skeletons to xtrax (StructureBundle base, loosened StageBundle accepting tuple/dict via Optional[Callable] relaxation, eager make_axis_dispatch executor) and have aminx subclass/wrap them with protein-specific fields. Directly resolves A2 (dispatch collision), A6 (bundle skeleton), and A7 (StageBundle validator) by design rather than by sequencing.
- [ai] Packaging — editable-path pin: aminx pyproject pins xtrax={path="../xtrax",editable=true} for lockstep dev; release builds repin to a published xtrax version. Simplest, matches A1 validation, but requires every contributor/CI to have ../xtrax checked out adjacent.
- [ai] Packaging — uv-workspace: Declare aminx+xtrax as members of a single uv workspace so the editable cross-link is implicit and lockfile-coherent. Best for tight co-evolution and atomic cross-repo PRs, but couples the two repos' release cadence and CI topology.
- [ai] Packaging — optional-extra: Make the xtrax dependency an optional extra (aminx[xtrax]) so the py3.13 bump and xtrax adoption are opt-in during transition; core aminx still installs on 3.12 until the cutover is forced. Lowest disruption but creates a dual-code-path maintenance burden until the extra becomes mandatory.
- [ai] make_axis_dispatch unification — rename aminx factory: Rename aminx's factory-style make_axis_dispatch (e.g. make_axis_dispatch_factory) so the xtrax eager name wins, avoiding shadowing. Cheapest, but leaves two distinct dispatch idioms (eager vs factory) coexisting and risks caller confusion.
- [ai] make_axis_dispatch unification — factory-over-executor: Keep aminx's factory semantics as the public API but implement it by composing xtrax's eager executor underneath (factory returns a closure that calls the xtrax executor). Unifies on one engine while preserving aminx's lazy/factory ergonomics; more glue code.
- [ai] make_axis_dispatch unification — adopt-eager wholesale: aminx drops its factory idiom and adopts xtrax's eager make_axis_dispatch directly, rewriting call sites. Cleanest long-term single semantics, but touches every dispatch caller and risks subtle JIT-recompile / static-field behavior changes on the inference path.
- [ai] StageBundle reconciliation — loosen xtrax validator: Relax xtrax StageBundle to accept tuple/dict fields (not only Optional[Callable]) so aminx StageSet drops in unmodified. Generic-friendly and zero aminx churn, but widens xtrax's public contract and weakens its type guarantees for all xtrax consumers.
- [ai] StageBundle reconciliation — wrap aminx StageSet: Keep xtrax StageBundle strict (Optional[Callable] only); aminx wraps its tuple/dict-bearing StageSet in an adapter that presents the strict interface to xtrax. Preserves xtrax's contract integrity; pushes the impedance-matching cost into aminx as an adapter layer.
- [ai] Checkpoint migration — metrics→extras mapping + migration tool: Adopt xtrax's single-PyTree orbax format, map aminx's Composite metrics subtree into the xtrax 'extras' slot, and ship a one-shot migration CLI that rewrites existing Composite ckpts to the new layout. Preserves all in-flight training runs; requires building and validating the migration tool.
- [ai] Checkpoint migration — clean-break, no back-compat: Adopt xtrax single-PyTree format with no migration tooling; old Composite ckpts are abandoned and runs restart from scratch under the new format. Minimal engineering, but discards existing checkpoint state — only acceptable if no long-running training must survive the cutover.
- [ai] Perf-regression guard — pytest-benchmark CI gate: Add a pytest-benchmark suite over the inference hotspots (io_callback drain, planner, ArrayRecord/HDF5 read, JIT recompile count) that fails CI on >X% regression. Fast, runs on every PR, but CPU-CI numbers may not represent on-cluster GPU/accelerator behavior.
- [ai] Perf-regression guard — bathos-sidecar cluster bench: Gate the inference-runner slice on a bathos-tracked cluster benchmark with a pre-registered sidecar comparing pre/post refactor throughput on real hardware. Authoritative on the actual perf hotspots; slower feedback loop and requires cluster scheduling per gate.
- [ai] Testing — aminx-owns-parity golden tests: aminx keeps a parity test suite that pins its pre-refactor tiling/sink/runner outputs as golden and asserts the xtrax-backed path reproduces them bit-for-bit. Boundary stays clear (aminx owns its acceptance criteria); xtrax remains unaware of protein specifics.
- [ai] Testing — shared conftest / cross-repo fixtures: Factor common tiling/dispatch test fixtures into a shared conftest usable by both repos so the same property tests run against xtrax primitives and aminx wrappers. Reduces duplicated test logic; introduces a test-time coupling and shared-fixture ownership question.
- [ai] Boundary-lint replacement (A4): Add an equivalent import-boundary guard so that moving primitives to xtrax.* does NOT silently bypass ADR 260605. Options: extend ruff TID251 to assert protein-domain modules never import-back from xtrax internals, or add a custom check that xtrax must stay protein-agnostic (no atom_37/residue_index symbols). Must land in the SAME change that introduces any xtrax.* import.
- [ai] Assumption-reversal — invert the dependency direction: Instead of aminx depending on xtrax, keep the rich tiling/runner primitives in aminx and have xtrax depend on (or re-export from) a thin shared core extracted from aminx. Challenges the premise that xtrax is the natural upstream; aminx's tiling is the more mature artifact, so the 'library' may belong on the aminx side.
- [ai] Assumption-reversal — do-not-move tiling at all: Adopt xtrax ONLY for training/engine/checkpoint/sparse/transforms and permanently keep all tiling + host sinks + plan in aminx, since they are the inference-perf hotspots AND the place where xtrax is thinnest. Questions whether the 12-module move is worth the cross-repo risk; the highest-value, lowest-risk subset may be the non-tiling surfaces only.
- [ai] Competing-faction — branch-by-abstraction with feature flag: Introduce a stable internal seam (a tiling/runner facade in aminx) behind a feature flag; implement the xtrax-backed path beside the legacy path, run both in shadow under the parity guard, then flip the flag once parity+perf gates pass and delete the legacy path. Decouples the cutover moment from the implementation work; enables instant rollback.

## Gate Measurement Protocol (makes the gates fixer-executable)

- **Bit-for-bit parity (idea 18):** Fixtures = the existing aminx parity golden set (`tests/parity/` 1ubq/1a00 + `minimal_bundle_fixture`) PLUS a production shape set enumerated from real run specs. Capture pre-refactor outputs (sequences, logits, scores, decoding_order) with a **fixed seed** (`jax.random.PRNGKey(0)`) on **CPU** with `JAX_ENABLE_X64` matching the path's dtype; assert exact array equality (`jnp.array_equal`, not tolerance) between legacy and xtrax-backed paths. CPU + fixed seed removes XLA/accelerator nondeterminism, so exact equality is achievable.
- **JIT-recompile count (idea 16):** Measure via a trace counter — wrap the jitted callable so each retrace increments a Python counter (or read `jax.jit`'s `_cache_size`/AOT lowering count). The fixture MUST instantiate every `eqx.field(static=True)` field on the bundle/StageSet (e.g. `decoder_sink`, `axis_boundaries`) at ≥2 distinct values so a divergent static signature shows as a count delta. Assert legacy count == xtrax-backed count.
- **Throughput regression (idea 17, T-R1-X = 5% hard / 0 target):** Op = end-to-end `sample`/`score` on the production shape distribution. Hardware = the target cluster node (record hostname); W warmup iters discarded (default W=3), S sampled iters (default S=20), report median ms/call. Let `r = (xtrax_median - legacy_median)/legacy_median`. **HARD FAIL** iff `r > 5%`. **Target 0%:** any `r ∈ (0%, 5%]` is logged as a defect and investigated under the T-R1-X adjudication rule (user owner; 3-attempt/5-day budget; close criterion = root cause documented AND re-run at r ≤ 0%); if fixable it MUST be fixed before legacy deletion (G3/G4/cutover); only an *unfixable* `r > 5%` with written root cause + user sign-off triggers the off-ramp. Bathos sidecar records jaxlib version, hostname, `XLA_FLAGS`-applied, W, S, and `r` (per AS4/T0.3). Standing gate, re-run on the production shape set, not one-shot.
- **Checkpoint round-trip (T1.4, T-R2=NO clean-break):** No migration golden (DROPPED with the clean-break decision). Single assertion: a **fresh** `ResumableState` save→load round-trips correctly (`jnp.array_equal` on model params + opt_state + step + RNG; metrics recovered from `extras`). The Composite→PyTree break is documented, not migrated.
